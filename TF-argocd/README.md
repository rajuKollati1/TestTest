# TF-ArgoCD - Complete Setup Guide

This folder contains Terraform configuration for deploying ArgoCD on a Kubernetes cluster using Helm.

## ⚡ Quick Start

```bash
# 1. Initialize Terraform
terraform init

# 2. Deploy ArgoCD
terraform apply

# 3. Get initial password
powershell -ExecutionPolicy Bypass -File './get-password.ps1'

# 4. Set new password (optional but recommended)
powershell -ExecutionPolicy Bypass -File './set-password.ps1' -NewPassword 'your-secure-password'

# 5. Access ArgoCD UI
# Option A: Port Forward
kubectl port-forward -n argocd svc/argocd-server 8080:443
# Then open: http://localhost:8080

# Option B: NodePort
# Get node IP and access: http://<node-ip>:30080
```

## Prerequisites

- Kubernetes cluster running and accessible
- `kubectl` configured to connect to your cluster
- `helm` installed (version 3.x or higher)
- Terraform installed (version 1.x or higher)
- `~/.kube/config` file properly configured
- PowerShell (for helper scripts)

## 📋 Detailed Installation Steps

### Step 1: Initialize Terraform

```bash
cd TF-argocd
terraform init
```

### Step 2: Plan the Deployment

```bash
terraform plan
```

### Step 3: Apply the Configuration

```bash
terraform apply
```

This will:
- Create the `argocd` namespace
- Create a 10Gi Persistent Volume Claim
- Deploy ArgoCD using Helm chart
- Configure all resource limits
- Set up NodePort service on port 30080

### Step 4: Monitor the Deployment

```bash
# Check pod status
kubectl get pods -n argocd

# Wait for all pods to be ready (1-2 minutes)
# Check services
kubectl get svc -n argocd
```

### Step 5: Retrieve Initial Admin Password

Use the helper script:

```powershell
powershell -ExecutionPolicy Bypass -File './get-password.ps1'
```

This will output:
```
Username: admin
Password: <auto-generated-password>
```

**OR manually retrieve it:**

**Windows PowerShell:**
```powershell
$secret = kubectl get secret argocd-initial-admin-secret -n argocd -o jsonpath="{.data.password}"
[System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String($secret))
```

**Linux/macOS:**
```bash
kubectl get secret argocd-initial-admin-secret -n argocd -o jsonpath="{.data.password}" | base64 -d; echo
```

### Step 6: Set New Admin Password (Recommended)

```powershell
powershell -ExecutionPolicy Bypass -File './set-password.ps1' -NewPassword 'admin@123'
```

This will:
- Connect to the ArgoCD server pod
- Update the admin password
- Display the new credentials

## 🌐 Access ArgoCD UI

### Option 1: Port Forward (Simplest for Development)

```powershell
kubectl port-forward -n argocd svc/argocd-server 8080:443
```

Then open: **http://localhost:8080**

### Option 2: NodePort (Direct Access)

```powershell
# Get the node IP

kubectl get svc -n argocd

```

## 📦 Deployment Configuration

The Terraform configuration deploys ArgoCD with:

### Namespace & Storage
- **Namespace**: `argocd`
- **Storage**: 10Gi PersistentVolumeClaim for data persistence

### Service Configuration
- **Type**: NodePort
- **Port**: 30080
- **Insecure Mode**: Enabled (development only)

### Component Resource Limits

| Component | Memory Request | Memory Limit | CPU Request | CPU Limit |
|-----------|----------------|--------------|-------------|-----------|
| Server | 256Mi | 512Mi | 100m | 500m |
| Repo Server | 256Mi | 512Mi | 100m | 500m |
| Controller | 256Mi | 512Mi | 100m | 500m |
| Dex Server | 128Mi | 256Mi | 50m | 200m |
| Notifications | 128Mi | 256Mi | 50m | 200m |

## 🔗 Connect Git Repository

After successful login, connect your Git repository:

```bash
# If using argocd CLI
argocd login <argocd-url>

# Add repository
argocd repo add https://github.com/YOUR-USERNAME/YOUR-REPO \
  --username <github-username> \
  --password <personal-access-token>
```

## 🚀 Create First Application

Create an ArgoCD application:

```bash
argocd app create my-app \
  --repo https://github.com/YOUR-USERNAME/YOUR-REPO \
  --path ./manifests \
  --dest-server https://kubernetes.default.svc \
  --dest-namespace default
```

## 🆘 Troubleshooting

### Password Not Retrieving

```powershell
# Check if secret exists
kubectl get secret -n argocd | findstr "initial-admin"

# Check pod logs
kubectl logs -n argocd deployment/argocd-server

# Verify pods are running
kubectl get pods -n argocd
```

### Pods Stuck in Pending

```powershell
# Describe pod to see issues
kubectl describe pod <pod-name> -n argocd

# Check node resources
kubectl describe nodes

# Check PVC status
kubectl get pvc -n argocd
kubectl describe pvc argocd-pvc -n argocd
```

### Cannot Connect to UI

```powershell
# Verify service is up
kubectl get svc -n argocd

# Test port forward
kubectl port-forward -n argocd svc/argocd-server 8080:443 -v=9

# Check firewall/network
# Ensure port 30080 is accessible (for NodePort)
# or port 8080 is accessible (for port-forward)
```

### Verify Helm Release

```bash
helm status argocd -n argocd
helm get values argocd -n argocd
helm get all argocd -n argocd
```

## 📝 Configuration Details in main.tf

Key settings you can modify:

```hcl
# Change NodePort
set {
  name  = "server.service.nodePort"
  value = "30080"  # Change this to another port
}

# Storage size
resource "kubernetes_persistent_volume_claim" "argocd_pvc" {
  # Change storage from 10Gi
  storage = "20Gi"
}

# Resource limits - adjust based on your cluster
set {
  name  = "server.resources.requests.memory"
  value = "256Mi"  # Increase if needed
}
```

## 🗑️ Cleanup

To remove ArgoCD from your cluster:

```bash
terraform destroy
```

This will:
- Remove the Helm release
- Delete the PersistentVolumeClaim
- Delete the namespace and all resources

## ⚙️ Production Considerations

For production deployments, consider:

1. **Enable TLS/SSL** - Set `server.insecure` to `false` and configure certificates
2. **Increase Resources** - Adjust memory and CPU limits based on your workload
3. **Enable RBAC** - Configure proper role-based access control
4. **Setup Backups** - Implement automated backups for the PVC
5. **Monitor Health** - Set up monitoring and alerting
6. **Use Private Registry** - Configure image pull secrets for private registries
7. **Implement Network Policies** - Restrict network access as needed
8. **Use Sealed Secrets** - For storing sensitive data securely
